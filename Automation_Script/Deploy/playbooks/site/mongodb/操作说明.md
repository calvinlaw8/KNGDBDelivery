# MongoDB 8.2.12 副本集验收说明

## 部署内容

- 副本集名称为 `rs0`，3 个成员地址由现场配置提供。
- 使用 keyFile 完成成员间认证，管理员账号只从受控配置获取。
- keyFile 必须为 `0400`，属主为 `mongodb:mongodb`。
- 部署时 keyFile 仅在控制节点 `/tmp/mongodb_auth` 临时生成，以 `umask 077` 创建；分发与权限验证完成或失败后都会删除控制节点临时目录。

## 受控入口

从交付根目录执行正式入口；首次使用交互式向导录入 MongoDB 的三节点拓扑后，可按组件范围部署或验证：

```bash
bash Automation_Script/Deploy/init_ansible.sh deploy --components mongodb
bash Automation_Script/Deploy/init_ansible.sh verify --components mongodb
```

`deploy` 会修改目标主机名、受管 hosts/inventory 块、软件和服务配置，执行前应具备 VM/磁盘快照和授权窗口。`verify` 不修改远端 MongoDB 数据或服务配置，但会生成本地日志与 checkpoint。失败后可按相同组件范围重新执行；常规入口不清空数据目录，也不提供事务回滚。

## 验收步骤

```bash
ansible-playbook -i inventory/hosts mongodb/01_install.yml mongodb/02_configure.yml mongodb/03_auth.yml mongodb/04_verify.yml
ansible mongodb -m shell -a "systemctl is-active mongod"
```

使用现场凭据在受控终端验证 `rs.status().ok = 1`，确认 1 个 Primary 和 2 个 Secondary。模拟单节点故障并记录重新选举结果。

## 风险边界

副本集写入和选举需要多数节点。多数节点所在 AZ 故障时，剩余单节点不能继续提供正常写入服务。

人工恢复或重建必须先确认可用备份、成员状态、Primary 选举状态和恢复责任人；不得将普通范围部署当作清空数据、强制重配副本集或故障切换演练入口。
