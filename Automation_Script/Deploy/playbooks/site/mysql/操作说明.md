# MySQL 8.4.11 GTID 主从 + Keepalived 验收说明

## 部署内容

- 1 个 Primary、2 个 Replica，节点地址和 VIP 由现场配置提供。
- 使用 GTID 异步复制，Keepalived 仅在本机 MySQL 可写时持有 VIP；本方案不提供 Replica 自动提升。
- root、复制账号和 VRRP 认证密码只从受控配置获取。

## 验收步骤

```bash
ansible-playbook -i inventory/hosts mysql/01_install.yml mysql/02_configure.yml mysql/03_replication.yml mysql/04_keepalived.yml mysql/05_verify.yml
ansible mysql -m shell -a "systemctl is-active mysqld keepalived"
```

使用现场凭据在受控终端确认 GTID、IO/SQL 线程、Replica `read_only` 和 VIP 状态。模拟 Primary 故障时，确认 VIP 不会漂移到只读 Replica；随后按人工提升、fencing、复制重建流程恢复业务并记录时间。

## 风险边界

本方案提供固定 Primary VIP，不提供 Replica 自动提升或自动重建复制。GTID 异步复制存在未同步事务丢失风险；原 Primary 恢复后不得直接重新加入，通常需要 fencing、全量重建并重新建立复制关系。
